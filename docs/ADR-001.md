# ADR-001 — Atlas 2: biblioteca pessoal unificada de componentes UI (offline)

**Status:** aceito · **Data:** 2026-10-06 · **Dono:** Felipe

## Contexto
O Atlas 1 provou o formato: um único `.html` com componentes reais do Animata (React + Tailwind v4 + Motion),
abrindo por duplo clique, sem servidor, sem CDN. O Atlas 2 deve virar a **biblioteca própria e permanente** de
componentes UI: tudo organizado, fácil de achar, funcionando offline em `file://`.

## Decisões

1. **Um catálogo, um HTML.** Todas as bibliotecas vão para um único `atlas.html` (sidebar por biblioteca/categoria,
   busca, ⌘K, favoritos, abas Preview / Código / Licença, copiar código).
2. **Código-fonte original, nunca reescrito.** `sources.lock.json` fixa repositório + commit + licença de cada fonte.
   `scripts/sync.mjs` clona no commit fixado, copia só os caminhos necessários para `vendor/<id>/` (verbatim + LICENSE)
   e audita a licença. Licença desconhecida/não permissiva → quarentena (não entra no build).
3. **Patches explícitos.** `vendor/` fica intocado; correções vivem em `patches/<id>.json` (find/replace) e são aplicadas
   no build. Cada patch é documentado e rastreável.
4. **Isolamento de CSS por biblioteca.** As libs têm tokens e keyframes conflitantes (Animata = triplets HSL,
   Magic UI = `oklch()`; ambas definem `--animate-*`). Solução: um compile Tailwind por biblioteca (sem preflight),
   pós-processado com PostCSS: todos os seletores ganham o prefixo `.lib-<id>`, `:root/html/body → .lib-<id>`,
   `.dark → .lib-<id>.dark`, `@keyframes` conflitantes são renomeados. O preflight é global e único (shell).
   Cada "palco" (stage) recebe `lib-<id>` + `dark|light`. Fallback se falhar: hub + um HTML por biblioteca.
5. **Alias `@/` por importador.** Cada lib usa `@/` para sua própria raiz; um plugin esbuild resolve `@/…` olhando de
   qual `vendor/<id>/` vem o arquivo importador.
6. **Adapters por biblioteca** geram `src/gen/<id>.gen.tsx` com o catálogo no schema unificado
   (`{id, lib, category, name, kind, Comp, source, deps, flags, license}`):
   Animata = stories do Storybook; Magic UI/Animate UI/Cult UI/Fancy/React Bits/SmoothUI = arquivos de demo/example.
7. **Offline de verdade.** Imagens remotas são baixadas no build (sharp, JPEG q70, ≤720px) e embutidas (base64);
   fontes em woff2/base64; zero requisições externas. Componentes que dependem de rede/servidor recebem a flag
   `needs-network` e ficam fora do build offline → vão para o **Atlas On**.
8. **Código-fonte embutido comprimido.** O código de cada componente vai gzip+base64 por biblioteca e é descomprimido
   sob demanda (`DecompressionStream`) na aba Código.
9. **Perfis de build.**
   - `pessoal`: tudo (inclui React Bits e Animate UI, que são MIT + Commons Clause — uso pessoal, não redistribuir).
   - `compartilhavel`: apenas MIT puro; lista de atribuições incluída.
10. **Futuro.** *Atlas On* (precisa de servidor/CDN/API) e *Atlas Low* (Preline, Flowbite, HyperUI, TW Elements,
    Material Tailwind, daisyUI, TailGrids, Uiverse — snippets HTML/CSS, adapter próprio).

## Consequências
- (+) Fonte verdadeira, atualizável (`sync` → `build`), licenças auditadas, nada reescrito.
- (+) Cada lib nova = 1 entrada no lock + 1 adapter + (talvez) 1 arquivo de patches.
- (−) HTML final grande (dezenas de MB no perfil completo); mitigação: perfis `lite/full`, código comprimido, montagem lazy.
- (−) Portais (Radix etc.) renderizam em `document.body` e perdem a classe `lib-<id>`; estratégia: container de portal
  por palco quando necessário.
- (−) Componentes com `window`-scroll/fixed/fullscreen precisam de tratamento (palco isolado ou modo tela cheia).

## Fases
0. Persistir pipeline do Atlas 1 em repo git (feito: `legacy/atlas1`).
1. Esqueleto: lock + sync + auditoria, schema, adapters `animata` + `magicui`, build unificado, QA em Chromium.
2. Demais libs (SmoothUI, Cult UI, Animate UI, Kokonut, Fancy, Motion Primitives, React Bits; Kibo opcional) — **concluída**.
3. Segunda onda após auditoria de licença (Eldora UI, lucide-animated, itshover, Spectrum UI, UI TripleD, ReUI, Kibo, Motiq) — **concluída**.
4. Perfis lite/full/compartilhável + carregamento por biblioteca (bundle gzip+base64 por lib dentro do HTML, executado sob demanda) — **concluída**.
5. Systaliko UI, Bundui e ThreeUI Community (todas MIT) + portais/overlays por lib — **concluída**. ThreeUI usa adaptador `custom` (catálogo = lista de renderers, sem arquivos de demo); páginas HTML completas rodam em iframe `srcDoc` e as que dependem de CDN (Tailwind Play, iconify, fontes) ficam `needs-network`.
6. (Aberta) **Atlas On**: componentes `needs-network`/`needs-files` com recursos remotos; **Atlas Low**: bibliotecas HTML/CSS (Preline, Flowbite, HyperUI, TW Elements, Material Tailwind, daisyUI, TailGrids, Uiverse) — requerem adaptador próprio sem React.
